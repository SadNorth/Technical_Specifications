# Technical_Specifications

Проект: маркетплейс репетиторов по программированию для детей
Контекст
Мы запускаем маркетплейс, который соединяет родителей и детей с репетиторами
по программированию. Проект на раннем этапе — используем managed-хостинг
(Vercel/Netlify) и managed-базы данных (Supabase), без своего кластера и без
Kubernetes. Нам важно с самого начала настроить автоматизацию деплоя и базовый
мониторинг, чтобы не собирать всё вручную по мере роста.
Задача
Настроить CI/CD-пайплайн для простого демо-приложения: при пуше в основную
ветку репозитория должны автоматически запускаться тесты/линтер и, если они
прошли — деплой на хостинг. Дополнительно — предложить базовую схему
мониторинга доступности сайта.
Вводные данные, которые можно использовать
• Приложение можно взять любое простое — свой мини-проект, шаблон
create-react-app/Next.js или даже статическую HTML-страницу с парой тестов
• Хостинг — на ваш выбор из бесплатных вариантов (Vercel, Netlify, GitHub Pages и
т.д.), не обязательно совпадает с тем, что использует Codenzo сейчас
• CI-система — любая (GitHub Actions предпочтительнее, так как это самый
распространённый бесплатный вариант, но подойдёт и GitLab CI)
Что нужно предоставить
• Ссылку на публичный репозиторий с настроенным пайплайном (файл
конфигурации CI)
• Пайплайн должен: устанавливать зависимости, запускать тесты/линтер, и
деплоить на хостинг при успешном прохождении
• Ссылку на задеплоенную версию приложения (чтобы можно было убедиться, что
всё реально работает)
• Короткое описание (полстраницы): как устроен пайплайн, какие шаги входят и
почему выбраны такие инструменты
• Схема или короткое описание, как бы вы настроили базовый мониторинг
доступности (например, через UptimeRobot, Sentry или другой инструмент) —
можно не внедрять реально, а просто описать подход
На что мы будем смотреть
• Пайплайн реально работает — деплой проходит автоматически, а не описан
только на словах
• Понимание, зачем нужен каждый шаг пайплайна, а не бездумное копирование
готового конфига
• Аккуратность конфигурации (читаемость, отсутствие лишнего)
• Разумность предложенного подхода к мониторингу — простое и рабочее решение
важнее переусложнённого
• Умение объяснить решения простыми словами
